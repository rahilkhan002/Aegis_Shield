## Executive Summary & Abstract

Financial fraud has evolved from unsophisticated, isolated credit card theft into distributed, multi-vector synthetic attacks—including rapid automated credential stuffing, Account Takeover (ATO), distributed transaction smurfing, synthetic identities, mule routing, and impossible geographic travel. Traditional machine learning pipelines built on static datasets or single-algorithm prototypes fail in modern financial environments due to three critical flaws: **lack of business rule integration**, **black-box unexplainability**, and **vulnerability to feature leakage and distribution drift**.

**AegisShield** is an enterprise-grade, real-time financial fraud detection and MLOps platform engineered to resolve these operational bottlenecks. Rather than relying on a standalone heuristic or an opaque machine learning model, AegisShield introduces a **Multi-Engine Risk Architecture** that harmonizes:
1. Declarative financial heuristics (`app/rules.yaml`),
2. Supervised tabular gradient-boosted decision trees (`HistGradientBoostingClassifier`),
3. Unsupervised geometric anomaly detection (`IsolationForest`),
4. Real-time sliding-window behavioral velocity tracking, and
5. Entity network graph linkage analysis.

These distinct signals are synthesized into a calibrated, continuous **0.0–100.0 Composite Risk Score** accompanied by automated 4-tier decision enforcement (`ALLOW`, `STEP_UP`, `MANUAL_REVIEW`, `BLOCK`) and concrete, human-readable reason codes generated by an Explainable AI (XAI) attribution engine.

From an engineering and DevOps perspective, the platform embodies full-lifecycle production readiness:
- **Serving Layer**: High-throughput asynchronous FastAPI microservice with 100% backward compatibility for legacy clients.
- **Serverless Cloud Deployment**: Zero-friction Vercel Python serverless deployment on Fluid Compute with ASGI path normalization middleware and dynamic SQLite `/tmp` storage.
- **Containerization**: Hardened multi-stage non-root Docker builds.
- **Orchestration**: Kubernetes manifests with Horizontal Pod Autoscaling (HPA) scaling between 2 and 10 replicas based on real-time CPU/memory utilization.
- **Continuous Delivery**: 15-stage Jenkins CI/CD pipeline enforcing Bandit SAST security analysis, unit/integration test suites (51/51 passing), automated model retraining, and automated rollback quality gates.
- **Observability**: Native Prometheus telemetry exposition (`/metrics`) integrated with pre-provisioned Grafana monitoring dashboards for latency percentiles and Population Stability Index (PSI) drift monitoring.

## 3. Mathematical Formulations & Core Algorithms

### 3.1 Kinematic Haversine Distance & Impossible Travel
To detect impossible physical travel between two sequential transactions without false positives from minor GPS jitter, AegisShield implements the Great-Circle Haversine metric:

$$\Delta\sigma = 2 \arcsin \left( \sqrt{\sin^2\left(\frac{\Delta\phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta\lambda}{2}\right)} \right)$$

$$d = R \cdot \Delta\sigma \quad \text{where } R = 6371.0 \text{ km}$$

$$\text{Velocity} = \frac{d}{\Delta t \text{ (hours)}} \quad (\text{km/h})$$

*Rule Trigger*: If $\Delta t < 2.0 \text{ hours}$ and $\text{Velocity} > 800.0 \text{ km/h}$, `RULE_IMPOSSIBLE_TRAVEL` fires with a critical weight of $30.0$, immediately elevating the transaction to `BLOCK` or `MANUAL_REVIEW`.

### 3.2 Behavioral Baseline Z-Score
Customer deviation from habitual spending behavior is quantified through rolling 30-day baseline statistics:

$$Z_{\text{amount}} = \frac{\text{Amount} - \mu_{30\text{d}}}{\max(\sigma_{30\text{d}}, 1.0)}$$

*Rule Trigger*: A $Z_{\text{amount}} \ge 4.0$ triggers `RULE_AMOUNT_ZSCORE_EXCEEDED` ($+18.0$ risk points).

### 3.3 Isolation Forest Calibrated Anomaly Scoring
The unsupervised Isolation Forest isolates anomalies by randomly partitioning feature space. Anomaly score $s$ for sample $x$ over tree ensemble size $n$ is:

$$s(x, n) = 2^{-\frac{E(h(x))}{c(n)}}$$

where $E(h(x))$ is the average path length across all isolation trees, and $c(n)$ is the average path length of unsuccessful searches in a Binary Search Tree (BST):

$$c(n) = 2 \left( \ln(n - 1) + 0.5772156649 \right) - \frac{2(n - 1)}{n}$$

AegisShield normalizes and calibrates this score into a continuous index $S_{\text{iso}} \in [0.0, 1.0]$.

### 3.4 Multi-Engine Weighted Risk Score Formula
The final composite risk score ($0.0$ to $100.0$) integrates all defensive layers:

$$\text{RiskScore} = \min\left(100.0, \; w_r \cdot S_{\text{rules}} + w_m \cdot (P_{\text{supervised}} \times 100) + w_i \cdot (S_{\text{iso}} \times 100) + w_v \cdot S_{\text{velocity}} + w_n \cdot S_{\text{network}}\right)$$

*Default Platform Weights*:
- Rule Heuristics Weight ($w_r$): **0.30**
- Supervised Probability Weight ($w_m$): **0.30**
- Unsupervised Isolation Forest Weight ($w_i$): **0.20**
- Behavioral Velocity Weight ($w_v$): **0.10**
- Entity Network Collision Weight ($w_n$): **0.10**

### 3.5 Population Stability Index (PSI) for Model Drift
To detect distribution shifts between baseline reference training data and live production transactions, the platform calculates PSI across $K=10$ quantile bins:

$$\text{PSI} = \sum_{k=1}^{K} \left( \text{Actual}_k - \text{Expected}_k \right) \times \ln\left(\frac{\text{Actual}_k}{\text{Expected}_k}\right)$$

*Operational Thresholds*:
- $\text{PSI} < 0.10$: **Stable / Nominal** (No action required).
- $0.10 \le \text{PSI} \le 0.25$: **Moderate Shift** (Monitor features, log telemetry alert).
- $\text{PSI} > 0.25$: **Significant Drift** (Triggers automated Jenkins retraining workflow).

## 5. Declarative Business Heuristics Engine

Implemented in [app/rules/engine.py](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/app/rules/engine.py) and configured via [app/rules.yaml](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/app/rules.yaml), the declarative engine evaluates live transaction features against human-authored risk policies:

```yaml
rules:
  - id: RULE_IMPOSSIBLE_TRAVEL
    name: "Impossible Geographic Travel Speed"
    weight: 30.0
    condition: "is_impossible_travel == 1.0"
    description: "Calculated speed between consecutive transactions exceeds 800 km/h."

  - id: RULE_VELOCITY_SPIKE_5M
    name: "Card Testing / Rapid Velocity Burst"
    weight: 20.0
    condition: "txn_count_5m >= 5.0"
    description: "Abnormal transaction frequency (>5 swipes in 5 minutes)."

  - id: RULE_AMOUNT_ZSCORE_EXCEEDED
    name: "Extreme Amount Outlier"
    weight: 18.0
    condition: "amount_zscore >= 4.0"
    description: "Transaction amount exceeds 4 standard deviations from 30-day baseline."

  - id: RULE_NEW_BENEFICIARY_HIGH_TRANSFER
    name: "High Value Transfer to New Payee"
    weight: 20.0
    condition: "is_new_beneficiary == 1.0 and amount_to_avg_ratio >= 2.5"
    description: "High value transaction dispatched to an unverified new beneficiary."

  - id: RULE_RAPID_FAILED_ATTEMPTS
    name: "Post-Credential Failure High Value Spend"
    weight: 15.0
    condition: "failed_attempts_last_24h >= 3.0 and amount >= 2000.0"
    description: "Multiple authentication failures followed by high-value debit."

  - id: RULE_UNUSUAL_NIGHTTIME_ACTIVITY
    name: "Anomalous Nighttime Spending"
    weight: 12.0
    condition: "is_nighttime == 1.0 and amount_to_avg_ratio >= 2.0"
    description: "Substantial transaction during low-activity hours (01:00 - 05:00 AM)."

  - id: RULE_SUSPICIOUS_DEVICE_SHARING
    name: "Multi-Account Device Collision"
    weight: 18.0
    condition: "device_associated_accounts >= 3.0"
    description: "Single physical device associated with 3 or more distinct bank accounts."

  - id: RULE_VPN_ANONYMOUS_IP
    name: "Anonymous Proxy / Tor Ingestion"
    weight: 14.0
    condition: "is_vpn_proxy == 1.0 and amount >= 5000.0"
    description: "High-value transaction originating from an anonymous VPN exit node."

  - id: RULE_HIGH_RISK_COUNTRY_OUTFLOW
    name: "Sanctioned / High-Risk AML Jurisdiction"
    weight: 25.0
    condition: "is_high_risk_country == 1.0"
    description: "Capital outflow to FATF-flagged high-risk financial jurisdiction."
```

## 9. Cloud & Serverless Deployment Mechanics (Vercel)

Deploying complex machine-learning stacks to serverless environments introduces strict constraints around **bundle size** and **filesystem permissions**. AegisShield implements targeted architectural solutions for Vercel:

### 9.1 Serverless Bundle Optimization (<500 MB)
Vercel enforces a 500 MB uncompressed function limit. Heavy machine-learning packages (such as native `xgboost` with CUDA/C++ binaries, uncompressed ~350 MB) push total bundle sizes to 682 MB.
- **Solution**: Segregated production dependencies ([requirements.txt](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/requirements.txt)) from offline testing dependencies ([requirements-dev.txt](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/requirements-dev.txt)).
- In production, gradient-boosted trees are evaluated via **`HistGradientBoostingClassifier`** (scikit-learn's native, highly optimized C-extension implementation), reducing the total uncompressed serverless bundle to **~160 MB** (76% size reduction).

### 9.2 ASGI Internal Rewrite Normalization
When Vercel routes traffic using `vercel.json` rewrites, internal serverless path translation can forward `/api/index.py` directly into the ASGI scope, causing 404 router misses.
- **Solution**: Implemented `VercelPathFixMiddleware` in [api/index.py](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/api/index.py), which inspects the ASGI HTTP scope and dynamically normalizes internal rewrite prefixes to root `/` or matching sub-routes.

### 9.3 Serverless Filesystem Adaptation (`/tmp`)
AWS Lambda and Vercel compute environments provide a read-only root filesystem, restricting disk writes exclusively to `/tmp`.
- **Solution**: In [app/db/session.py](file:///c:/College/Projects/Anti%20Gravity/DevOps/mlops-fraud-pipeline/app/db/session.py), the SQLite connection string dynamically routes to `/tmp/fraud_pipeline.db` upon detecting `os.getenv("VERCEL")`, guaranteeing crash-free database writes for transaction auditing, alert generation, and analyst feedback.
